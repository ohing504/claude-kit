# usage — 세션 하나가 쓴 호출 수와 토큰과 소요

```bash
usage <세션 ID>            # 표로 출력
usage <transcript 경로>    # 같음
usage <세션 ID> --json     # 원시 수치 (전후 비교용)
usage <세션 ID> --until 24 # 24번째 요청까지만
usage <세션 ID> --marks    # 단계 경계 후보를 요청 번호와 함께
usage <세션 ID> --from 15 --until 21   # 그 구간만
```

세션 ID만 주면 `~/.claude/projects/` 아래 전체에서 찾는다. 세션 파일이 어느 프로젝트 폴더에
들어가는지는 실행 당시 cwd가 정하므로 저장소 슬러그만 보면 못 찾는다.

실행이 끝난 세션에서 더 작업하지 않는다. 세션 파일에 뒤로 행이 더 붙으면 합계와 소요가 바뀐다 —
같은 세션 ID로 다시 재면 앞서 잰 값과 어긋난다.

## 출력이 담는 것

- 메인과 서브에이전트를 나눈 호출 수와 토큰. 서브에이전트에는 종류와 호출 순서가 붙고, 메인이
  띄운 수보다 적게 찾으면 그 이름이 경고로 나온다. 서브에이전트가 띄운 서브에이전트는 메인의
  Agent 호출에 없어 `agent-<id>.meta.json`에서 종류와 부모를 읽고 부모 순번 뒤에 붙는다.
  서브에이전트의 transcript 파일은 `--json`의 `agents[].agent_id`로 찾는다 — Agent 도구로
  띄운 것은 `<세션 ID>/subagents/agent-<agent_id>.jsonl`, teammate로 띄운 것은
  `<agent_id>.jsonl`이다
- `cache write`를 5분과 1시간으로 가른 값, `output` 중 thinking
- 낸 글자 수 — 답한 행의 `text` 블록과 `tool_use` 입력을 합한 자 수. thinking 블록은 본문이 빈
  채로 저장돼 셀 것이 없다. `output` 뒤의 `?`는 낸 글자와 어긋나는 응답이 그 안에 있어 값이
  실제보다 작다는 표시다 — 어긋난 응답 수는 표 아래 경고에 나온다
- 도구별 결과 자 수. 이미지는 자 수에서 빼고 장수와 토큰으로 따로 낸다
- 서브에이전트마다 연 이미지 장수와 그 토큰 — 한 번에 이미지를 몇 장까지 넣을지 정할 때 쓴다
- 한 요청에 도구를 몇 개 담았는지의 분포와, 둘 이상 담은 요청의 수와 비율 (메인). 도구를 하나도
  부르지 않은 요청은 담을 것이 없어 분모에서 뺀다
- Bash 호출을 명령을 어떻게 이었는지로 가른 수와, 명령을 둘 이상 담은 호출 중 구획 마커가 붙은
  비율. 선행 `cd`와 조건 판정(`[ ... ] &&`)은 명령으로 세지 않는다
- 두 번 이상 연 파일과 그 횟수 (메인). `Read`와 셸이 전문을 실은 명령(`cat`, `head`, `tail` 등)을
  합해 세고, 한 요청에 담아 연 것은 결과가 한 번에 실리므로 한 번으로 센다
- 요청마다 그때 실린 컨텍스트와 부른 도구, 컨텍스트가 급락한 자리의 압축 표시
- 소요를 도구가 돈 시간과 모델이 문 시간과 서브에이전트에 위임한 동안과 사람이 답을 쓴 시간으로
  가른 값, 1분을 넘긴 도구 호출의 명령

무엇을 명령 하나로 세고 무엇을 구획 마커로 보는지는 `tests/test_session.py`가 정한다.

`--until N`은 N번째 요청까지만 세고 그 뒤에 뜬 서브에이전트도 뺀다. `--from N`은 N번째부터 세고
그 앞에서 뜬 서브에이전트를 뺀다. 둘은 양끝을 포함하고 함께 쓴다. **자른 구간에서도 요청 번호는
세션 전체 기준이다** — 구간마다 1부터 다시 세면 다음 구간을 어디서 자를지 정할 수 없다.

`--marks`는 단계를 여는 호출을 요청 번호와 함께 낸다. `Skill` 호출과 `Agent` 호출을 낸다. 이 둘은
Claude Code가 정한 도구 이름이므로 어느 저장소에서 실행한 세션이든 같은 뜻을 갖는다.

셸 호출은 기본으로 내지 않는다. 어느 셸 명령이 단계를 여는지는 저장소마다 다르고, 그 판정을 이
도구에 적으면 저장소가 늘 때마다 이 도구를 고쳐야 한다. 조건 없이 전부 내면 한 세션에 백 건을
넘어 경계를 고를 수 없다. 셸 호출이 필요하면 `--marks-bash`에 정규식을 준다.

```bash
usage <세션 ID> --marks --marks-bash 'make (\w+)'
usage <세션 ID> --marks --marks-bash '/tools/[\w-]+"?\s+([\w-]+)\s+([\w-]+)'
```

정규식에 잡는 그룹이 있으면 잡은 값을 공백으로 이어 이름으로 쓰고, 그룹이 없으면 정규식에 맞은
문자열 전체를 이름으로 쓴다. 위 두 번째 예는 저장소가 명령줄 도구를 `tools/<이름>/`에 두고
`uv run --project .../tools/<이름> <이름> <하위명령>`으로 부르는 배치에서 그 호출을 잡는다.

**단계 이름은 붙이지 않는다.** 무엇이 어느 단계인지는 저장소마다 달라, 이 도구에 적으면 저장소가
늘 때마다 도구를 고쳐야 한다. 이름은 그 값을 싣는 문서가 붙인다.

**필요한 수치가 없으면 스크립트를 짜지 말고 이 도구에 넣는다.** 그 자리에서 짠 스크립트는
검증되지 않고 저장되지 않아 같은 실수가 세션마다 되풀이된다. 테스트를 먼저 쓰고 여기에 넣는다.

## 내지 않는 것

- **금액** — 구독 크레딧으로 실행되므로 API 정가를 곱한 값이 실제 청구와 자릿수가 맞지 않는다
- **작업 하나당 값** — 한 세션에 여러 작업이 섞인다. 작업 하나의 값을 재려면 그 작업만 도는 세션을
  따로 돌리거나 `--from`과 `--until`로 구간을 자른다
- **teammate의 대기 시간** — teammate 세션 행에 `origin`이 없어 대기를 가를 근거가 없다. 0으로 나온다

```bash
usage <세션 ID>
```
