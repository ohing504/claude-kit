# CLAUDE.md 특화 점검

대상이 CLAUDE.md(또는 변형 — `CLAUDE.local.md`, `~/.claude/CLAUDE.md`, monorepo 서브디렉토리 CLAUDE.md)일 때 SKILL.md 범용 점검에 *더해* 적용한다.

## 추가 삭제 신호

- 범용 best practice·일반론(이 프로젝트 특정이 아닌 조언) → **삭제**. CLAUDE.md는 *이 프로젝트에서만 참인 것*만 담는다.
- 여러 CLAUDE.md(루트·서브디렉토리·`~/.claude`)에 같은 내용 중복 → 가장 가까운 한 곳만 두고 **pointer**.
- 일회성 이력(해결된 버그·특정 커밋·날짜)이 CLAUDE.md에 특히 자주 낀다 → **삭제** (범용 신호 재확인).
- **린터가 할 일을 지시로 적어둔 것** → **삭제**. 코드 스타일 규칙과 예시 코드는 무관한 컨텍스트를 매 세션 쌓아 지시 준수를 떨어뜨린다. LLM은 in-context learner라 주변 코드를 보면 관례를 따라가므로, 결정론적으로 잡을 수 있는 것은 linter, formatter, hook으로 옮기고 문서에는 "주변 코드에 맞춘다" 수준의 판단 프레이밍만 남긴다.
- **하네스 기본 프롬프트와 겹치는 지시** → **삭제**. 하네스가 이미 주입하는 문구를 재서술하면 모델이 어느 쪽을 따를지 고르느라 추론을 낭비한다. 겹침이 의심되면 실제 시스템 프롬프트와 대조해 확인한 것만 지운다.

## 함께 로드되는 것과 대조

매 세션 로드되는 것은 CLAUDE.md만이 아니다. Output Style, `rules/`(`paths` 조건이 없으면 항상), UserPromptSubmit 훅의 `additionalContext`, 하네스 시스템 프롬프트가 같은 컨텍스트에 함께 들어온다. CLAUDE.md를 고치기 전에 그 파일들을 열어 대조한다.

- **한쪽이 금지한 표기를 다른 쪽이 예시로 쓰고 있음** → **양쪽을 맞춘다**. 지시와 예시가 어긋나면 어느 쪽도 안정적으로 따라지지 않는다. 고쳐야 할 곳이 CLAUDE.md가 아니라 그 다른 파일인 경우가 있다.
- **같은 지시가 여러 겹으로 들어옴**(Output Style, 훅 재주입, CLAUDE.md) → 한 곳만 남기고 나머지를 삭제 후보로 올린다.

## 누락 플래그 — 플래그만, 추가는 사용자 확인

아래 핵심이 없으면 *플래그*한다. 무엇을 채울지는 사용자가 정한다 — 이 스킬은 내용을 창작하지 않는다.

- **자주 쓰는 명령** — build·test·lint·run 등 (매번 탐색하게 만드는 누락)
- **아키텍처 개요** — 코드 구조만 봐서는 알 수 없는 경계에 한정한다. 디렉토리 이름과 실제 책임이 다르거나, 진입점이 여러 개라 어디부터 읽어야 할지 코드에 나타나지 않을 때만 플래그한다.
- **gotcha·함정** — 코드만 봐선 모르는 비자명 제약·관례
- **테스트 방법** — 어떻게 돌리고 무엇을 PASS로 보는지
- **코드 컨벤션** — 프로젝트 고유 네이밍·패턴 (범용 스타일 말고)

## stale 플래그 — 플래그만, 삭제는 사용자 확인

- 존재하지 않는 경로·파일·앵커를 가리키는 참조
- 실패할 명령(틀린 경로·삭제된 스크립트)
- 더는 맞지 않는 디렉토리 구조 서술

stale 판정은 코드베이스 cross-check 영역이라 형식 다이어트 범위를 넘는다 — 의심을 *플래그*하고 실제 수정은 사용자 확인.

## 위치별 성격 — 점검 기준이 달라진다

- **프로젝트 루트 `CLAUDE.md`** — 팀 공유·커밋됨. 위 누락 플래그·삭제 신호를 정상 적용.
- **`CLAUDE.local.md`** — gitignore·개인·임시(진행 중 사이클 한정). 누락 플래그 기준 완화 — 임시 메모라 완결성을 요구하지 않는다.
- **`~/.claude/CLAUDE.md`** — 전 프로젝트 공유 개인 룰. *프로젝트 특정* 누락(명령·아키텍처)은 플래그하지 않는다 — 범용 룰이라 없는 게 정상. 모델이 맥락에서 도출할 수 있는 것(주변 코드 스타일, 일반 개발 관례)은 삭제 후보지만, 개인 선호(표기 규칙, 응답 형식, 호칭)는 어디에도 단서가 없어 도출되지 않으므로 유지한다.
- **monorepo 서브디렉토리 `CLAUDE.md`** — 그 하위 트리 한정. 루트와 중복되는 내용은 삭제 신호(루트로 pointer).

## 자동 생성분을 만나면

`/init`이나 유사 자동 생성으로 만든 CLAUDE.md는 삭제 후보가 특히 많다. 모든 세션과 모든 산출물에 들어가는 파일이라 한 줄의 오류가 계획과 코드로 증폭된다. 자동 생성 흔적(디렉토리 나열, 의존성 목록, 코드에서 읽어낼 수 있는 구조 서술)이 보이면 한 줄씩 존치 근거를 물어 정리한다.
