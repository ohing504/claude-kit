# token-usage-review

`usage` 명령줄 도구로 세션 기록의 잔존 비용(크기 × 그것이 컨텍스트에 남아 있던 요청 수)을 재고, 어느 스킬, 도구 결과, 파일, 세션 운영 방식이 비싼지 리포트로 낸다. 리포트를 제시하고 무엇을 고칠지 확인받는 데서 멈춘다 — 실제 수정은 이 스킬의 범위 밖이다.

## Context

- 현재 경로: !`pwd`
- 인자: `$ARGUMENTS`

## 인자

- 인자 없음 → 현재 저장소(위 `pwd`)의 프로젝트만 본다.
- `--all` → 프로젝트로 좁히지 않고 코퍼스 전체를 본다.
- `<project-slug>` → 그 슬러그의 프로젝트만 본다. 슬러그는 `~/.claude/projects/` 아래 디렉터리 이름과 정확히 같다.
- `--since <YYYY-MM-DD>`, `--until <YYYY-MM-DD>` → 그 기간의 세션만 본다.
- `--top <N>` → 축마다 상위 몇 행을 실을지. 상한 20. 20을 넘겨 요청하면 20으로 자른다.

## 흐름

인덱스 갱신 → 수집 → 리포트 → 개선안 제시 → 확인. 고치지 않는다.

1. **설치본 확인** — `usage corpus --help`를 실행한다. 종료 코드가 0이 아니거나 `invalid choice: 'corpus'`가 나오면 설치본에 `corpus`가 없다. Edge Cases의 "구버전 설치본"을 따른다.
2. **범위 확정** — `$ARGUMENTS`를 해석해 프로젝트 슬러그, `--all` 여부, 기간, `--top`을 정한다.
3. **슬러그 결정** — `--all`이 아니면: 위 Context의 `pwd` 값에서 영숫자가 아닌 문자를 전부 `-`로 바꿔 후보 슬러그를 만든다. `ls ~/.claude/projects/<후보>`로 존재를 확인한다. 없으면 `ls ~/.claude/projects`로 목록을 받아 경로 꼬리가 맞는 후보를 사용자에게 제시하고 고르게 한다.
4. **인덱스 갱신** — `usage index`를 실행한다. 초회는 코퍼스 전체를 다시 읽어 오래 걸릴 수 있으므로 타임아웃을 600000ms로 준다. 출력 JSON의 `indexed`, `skipped`, `failed`를 기록해 둔다.
5. **수집** — 아래 `## 수집`의 명령 2개를 그대로 실행한다. 명령을 늘리지 않는다.
6. **되짚기** — 개선안의 근거가 될 상위 항목에 한해, 최대 2개 세션에서 `usage session <session_id> --table --from <order> --until <order>`를 실행해 실제 요청 내용을 확인한다. 3개 이상 실행하지 않는다.
7. **리포트 제시** — `## 리포트 형식`대로 응답 본문에 마크다운으로 낸다. 파일로 저장하지 않는다.
8. **확인** — 개선안에 번호를 붙여 어느 항목을 진행할지 한 번에 묻는다. 답을 받으면 그 항목을 다룰 곳(해당 스킬 문서, `ai-doc-improver`, 세션 운영 습관 변경)을 지목하고 끝낸다. 실제 수정은 이 스킬에서 하지 않는다.

## 수집

`<슬러그>`는 3단계에서 정한 값, `<top>`은 2단계에서 정한 값(기본 8, `--all`이면 5)으로 채운다. `--since`/`--until`이 주어졌으면 두 명령 모두에 그대로 붙인다.

```text
usage corpus --project=<슬러그> --top <top> --table
usage corpus --project=<슬러그> --check --table
```

`<슬러그>`는 `-`로 시작하므로 `--project <슬러그>`로 띄어 쓰면 argparse가 슬러그를 옵션으로 오인해 `expected one argument` 에러가 난다. 반드시 `--project=<슬러그>` 형식을 쓴다.

`--all`이면 `--project=<슬러그>`를 빼고 나머지는 그대로 쓴다.

- `--table`을 쓰고 JSON을 쓰지 않는다. JSON은 들여쓰기가 있어 같은 내용에 토큰이 더 들고, `--table`의 각 행에도 되짚기에 필요한 `<session_id>#<order>`가 실린다.
- `--by`를 지정하지 않는다. 지정하지 않으면 skill, agent, tool, file, project, period, length, compaction, spread 9개 축이 한 번에 나온다. 축마다 따로 부르면 명령이 9번이 되고 머리말이 9번 중복된다.

## 리포트 형식

사실과 판단을 구역과 접두 라벨로 두 겹으로 가른다. 근거를 대지 못하는 문장은 쓰지 않는다.

### 머리말 (전부 도구 출력)

- `--table` 첫 줄의 계측 경계 문구를 그대로 인용한다.
- `usage index`의 `indexed`, `skipped`, `failed`.
- `--check`의 `ok`, `violations` 개수, `unattributed_residual`, `eviction_events`.
- 적용한 필터(프로젝트 슬러그 또는 `--all`, 기간, `--top`)와 실행한 명령 원문.

### 1부 측정값 (표만, 해석 문장 없음)

각 행에 `<session_id 앞 8자>#<order>` 근거 열을 둔다. 싣는 축과 행 수:

- summary — sessions, scopes, requests, compaction_ratio
- skill — 상위 `<top>`행 (residual, size, count, sessions, 근거)
- tool — 상위 `<top>`행
- file — 상위 `<top>`행
- agent — 상위 5행 (paid_by_parent, spent_by_self, calls, scopes)
- length — 구간 전부 (요청당 평균 잔존)
- compaction — 전부
- spread — 상위 5행 (mean, min, median, p95, max)
- period, project — `--all`일 때만

### 2부 판단

문장마다 `판단:` 접두를 붙이고 괄호로 근거 행을 가리킨다. 예: `판단: 이 스킬은 크기 순위 4위인데 잔존 순위 1위다 (skill 축 1행, size 12k, residual 480k).`

### 3부 개선안

`## 개선안 항목` 서식을 따른다.

## 개선안 항목

기획이 정한 갈래 셋에 실측에서 자주 나오는 갈래 하나를 더해 네 갈래로 낸다. 갈래마다 0개 이상이고, 없으면 "이 갈래는 개선 후보가 잡히지 않았다"고 적는다.

- **A. 스킬과 에이전트 정의** — skill 축과 agent 축에서 낸다. agent 축은 `paid_by_parent`와 `spent_by_self`를 대조해 위임이 실제로 아꼈는지 본다.
- **B. 세션 운영** — length 축(어느 구간부터 요청당 평균이 뛰는지), compaction 축(압축 뒤 구간이 더 비싼지), summary의 `compaction_ratio`에서 낸다.
- **C. 파이프라인 구조** — spread 축에서 낸다. 같은 키 안에서 min과 p95의 배수가 큰 자리가 개선 여지다.
- **D. 도구 사용 습관** — tool 축과 file 축에서 낸다. 같은 파일을 여러 세션에서 반복해 읽는 것이 여기 잡힌다.

항목마다 아래 6줄 고정 서식을 쓴다.

```text
### N. <한 줄 제목>
- 측정값: <표 행 인용, 숫자 그대로>
- 되짚기: usage session <session_id> --table --from <order> --until <order>
- 판단: <왜 이것이 개선 여지인지>
- 제안: <무엇을 어떻게 바꿀지, 한 가지만>
- 예상 효과: <어느 수치가 얼마나 줄 것으로 보는지와 그 근거>
- 확인할 것: <이 제안을 채택하기 전에 사용자가 답해야 하는 질문>
```

## 원칙

- **잔존 비용으로 순위를 매긴다.** 크기 순위와 잔존 순위가 갈리는 자리가 호출 시점 때문에 비싼 것이다.
- **수치는 도구만 낸다.** 개선 규칙을 이 문서에 표로 박지 않는다. 표에 박으면 그 규칙이 낡았을 때 수치까지 함께 틀린다.
- **근거 없는 판단을 쓰지 않는다.** 표 행을 가리키지 못하는 문장은 리포트에서 뺀다.
- **경계를 매번 적는다.** 세션 기록에 남지 않는 소비(웹 검색, 페이지 읽기 같은 내부 경로)가 있어 청구 총액과 어긋난다. 이것은 결함이 아니라 자료의 한계다.
- **명령을 늘리지 않는다.** 수집은 두 번, 되짚기는 최대 두 번이다.

## 하지 않는 것

- 파일 수정, 설정 변경, 스킬 문서 재작성. 제시까지만 한다.
- 리포트를 파일로 저장. 응답 본문에만 낸다.
- 청구 금액이나 요금제 한도 환산.
- 수치를 얻으려 임시 스크립트를 짠다. 필요한 수치가 도구에 없으면 그 사실을 도구에 넣을 항목으로 보고한다.
- 인덱스 갱신 생략. 매 실행 `usage index`를 먼저 돌린다.

## Edge Cases

- **구버전 설치본**: `usage corpus --help`가 실패한다. `uv tool install --force <usage 도구의 pyproject.toml이 있는 경로>`를 제시하고 실행 여부를 사용자에게 묻는다. 이 명령은 `allowed-tools`에 없어 실행 자체가 권한 프롬프트를 거치므로 확인 게이트가 된다. 거절하면 리포트를 만들지 않고 멈춘다.
- **`usage`가 PATH에 없음**: 설치 명령을 안내하고 멈춘다. 다른 경로로 우회 실행하지 않는다.
- **인덱싱 실패 세션이 있음**: `usage index`의 `failed`가 0보다 크면 그 수를 머리말에 적는다. `failed`가 크면 순위가 코퍼스 일부만 반영한 값이라는 문장을 붙인다.
- **`--check`가 위반을 냄**: 수치는 그대로 싣되 머리말에 위반 수와 `eviction_events`를 적고, 잔존 순위를 확정이 아니라 근사로 다룬다는 문장을 붙인다. 위반이 있어도 리포트를 중단하지 않는다.
- **슬러그가 인덱스에 없거나 세션 0개**: `ls ~/.claude/projects`로 후보를 제시하고 사용자가 고르게 한다. 임의로 비슷한 슬러그를 골라 진행하지 않는다.
- **세션 표본이 적음 (스코프 5개 미만)**: 순위를 내지 않고 측정값만 낸다. 개선안 대신 "표본이 더 쌓인 뒤 다시 볼 것"을 적는다.
- **진행 중인 현재 세션이 인덱스에 들어감**: 실행 중인 세션은 뒤로 행이 더 붙어 값이 바뀐다. 리포트에 그 session_id를 적고, 그 세션 단독 수치를 개선 근거로 쓰지 않는다.
- **`base` 항목이 상위에 옴**: 요청 1의 컨텍스트(시스템 프롬프트, 지침, 메모리)는 내부 구성이 세션 기록에 남지 않아 하나로만 잡힌다. 쪼갤 수 없다는 사실을 적고 지침과 메모리 크기의 근사로만 다룬다.
- **agent 축의 두 값을 대조할 때**: `paid_by_parent`와 `spent_by_self`는 서로 다른 스코프에서 나와 같은 호출을 1대1로 가리키지 않는다. 차액을 절감액으로 계산하지 않는다.
- **`--top`을 20보다 크게 요청**: 20으로 자르고 자른 사실을 머리말에 적는다.
- **`--all`에 기간 필터가 없어 표가 큼**: `--top 5`로 낮춘다. 그래도 크면 `--since`로 최근 3개월을 좁히도록 사용자에게 제안한다.
- **개선 여지가 안 잡힘**: 억지로 항목을 만들지 않는다. 측정값과 "현재 실측에서 개선 후보가 잡히지 않았다"를 적고 끝낸다.
- **사용자가 곧바로 수정을 요구**: 범위 밖이라고 알린다. 문서 수정이면 `ai-doc-improver`로, 세션 운영이면 습관 변경으로 넘긴다.
- **첫 `usage index`가 오래 걸림**: 초회는 코퍼스 전체를 다시 읽어 오래 걸린다. 타임아웃 600000ms로 실행하고, 그래도 끝나지 않으면 그 사실을 알리고 사용자 판단을 받는다.
