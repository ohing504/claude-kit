claude-kit  ·  skill

prompt-forge

대충 던진 요청을 반응형 인터뷰로 파고들어, 실행에 붙여넣을 의도 명세로 벼리는 도구.

문구를 다듬는 게 아니라 무엇을 시킬지를 뽑는다 — 원샷·loop일수록 값이 오른다
01

왜 필요한가

좋은 결과는 프롬프트를 예쁘게 다듬어서가 아니라, 모델에게 무엇을 시킬지 — 의도 — 를 명확히 전달하는 데에서 나온다. 대충 던지면 모델이 빈칸을 제멋대로 채우고, 자동화가 깊어질수록 그 틈은 커진다.

01

모호하면 추측한다

대충 던진 요청의 빈칸을 모델이 제멋대로 메운다. 시킨 사람의 의도와 어긋난 채로.

02

강할수록 증폭한다

강한 모델·되물음 없는 원샷일수록 모호를 "확신 있게, 정교하게 틀린" 결과로 키운다.

03

반복이 키운다

loop이 자동으로 N회 돌면, 틀린 방향으로 great efficiency로 N번 간다. 시드가 결과를 가른다.

02

언제 도는가

발동한다

  • 다른 실행에 시킬 프롬프트가 필요할 때 — "이거 시킬 프롬프트 짜줘", "loop 돌릴 goal 명세 만들어줘"
  • 요청이 짧거나 모호할수록, 되물을 수 없는 원샷·반복 실행일 때 값이 크다

나서지 않는다

  • 이미 있는 문서·프롬프트 다듬기 — ai-doc-improver 소관
  • 프롬프트를 세션 안에서 실행하는 것 — 산출은 명세 텍스트까지, 실행은 사용자가 딴 데서
03

어떻게 도는가

인터뷰로 의도를 정밀화한 뒤에야 명세를 쓴다 — 건너뛰고 바로 쓰지 않는 게 규칙이다.

1 · 입력
rough ask
대충 시키고 싶은 것을 받는다. $ARGUMENTS 또는 발화에서.
→
2 · 자동
타깃 식별
이 명세를 어디에 쓸지. 타깃이 구조·강조점을 바꾼다.
→
3 · 대화
반응형 인터뷰
한 번에 1–2개씩, 답에 반응해 고도화. 의도·시나리오·크리티컬만 묻는다.
→
4 · 자동
의도 명세 작성
골격대로. 못 채운 칸은 가정으로 명시(몰래 심지 않는다).
→
5 · 자동
출력 · 저장
짧으면 복붙, 길면 파일. 어느 쪽이든 검토 요약(의도·크리티컬)을 함께.
사람 입력 자동 사람 ↔ AI 왕복
심장
인터뷰가 이 도구의 심장이다. 요청이 상세해도 질문 1회로 의도를 더 좁힌다 — 원샷·loop에서 모델이 추측할 여지를 이 왕복이 미리 없앤다.
04

무엇을 묻나 — 의도만, 구현은 열어둔다

질문 수가 아니라 답에 반응하는 질문이 품질을 만든다 — 그 질문은 의도만 겨눈다.

묻는다 · 의도

  • 목적 — 궁극에 뭘 얻나. 성공한 결과는 어떤 모습인가(성공 기준)
  • 시나리오 — 입력은 뭐고 출력은 어디 쓰이나. 누가·언제 실행하나
  • 크리티컬 결정 — 되돌리기 어렵거나 값 큰 선택(범위·보안·반드시 지킬 제약)
  • 실패 모드 — 특히 걱정되는 오작동·엣지 (ultracode 타깃에서 중요)

안 묻는다 · 구현

  • 코드 표현·변수명·라이브러리 선택·N 값 같은 세부
  • 문구 다듬기 — 프롬프트가 열어두거나 실행 측 자율에 맡긴다
안 묻는다고 방치가 아니다 — 답이 모호하면 그 자리서 파고든다("빠르게"가 지연인가 처리량인가). 의도는 끝까지 좁히고 구현 세부만 자율로 연다.
05

타깃별 델타 — 어디 쓰느냐가 명세를 바꾼다

같은 의도라도 어디서 실행하느냐에 따라 더할 것이 다르다 — 타깃 하나의 델타만 얹는다.

타깃명세에 더하는 것한 줄 원칙
ultracode엣지·실패 모드 열거, 자체 검증·애드버서리얼 체크 요구, 되돌리기 어려운 동작 전 확인 게이트, 검증 증거(테스트·실행) 요구안정 > 속도
Fable 원샷모든 맥락을 앞에 몰아넣기(뒤늦은 참조 금지), 출력 계약 엄격 고정(형식·길이·포함/제외), 되묻지 말고 명시한 가정으로 진행애매함 제로
loop 시드NEW목표 + 완료 정의(definition-of-done) + 검증자(테스트·스키마·diff 등 자동 판별 수단) + 종료조건을 대화가 아니라 바깥 파일에 반복 재현되게 고정매 반복 재현
일반 에이전트위 둘의 중간. 구조·성공 기준·제약은 유지하되 상호작용 여지를 열어둔다(막히면 되물어도 됨)균형
loop 시드는 런타임이 자동 반복하며 매 회 읽는 명세다. 검증자가 없으면 loop은 오답을 성공으로 오판하므로, 자동 판별 수단이 핵심이다.
06

의도 명세의 골격

산출물은 이 골격을 채운다 — 맥락을 앞에, 출력 계약을 뒤에 두는 순서가 정확도를 높인다.

[역할] 무엇으로서 작업하는가 (필요 시) [맥락] 배경·입력·전제 # Fable 원샷이면 모든 정보를 여기 앞에 몰아넣는다 [목표] 달성할 것 + 성공 기준 (성공한 결과의 구체적 모습) [단계] 모호어 없는 명시적 번호 단계 (필요한 것만, 억지 분해 금지) [제약] 반드시 지킬 것 / 절대 하면 안 되는 것 / 크리티컬 결정 [출력] 형식·길이·포함·제외 # 엄격히 [타깃 델타] 위 05에서 해당분 하나

모호어 제거

"적절히·알아서·필요에 따라"를 명시 단계·기준으로 대체한다. 명세에 애매함을 남기지 않는 게 인터뷰의 목적이었다.

긍정형 지시

금지 나열보다 "무엇을 하라". 근거 없는 대문자 명령(ALWAYS/NEVER) 대신 이유를 동반한 서술로.
