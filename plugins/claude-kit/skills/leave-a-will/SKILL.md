# leave-a-will

세션을 닫거나 새 세션으로 넘어가기 전에, 이 세션에만 있는 정보를 잃지 않게 한다. 결과는 둘 중 하나다.

- **잃을 것 없음**: 남은 항목이 없거나 전부 처분했다. 무엇을 확인했는지 목록으로 보인다.
- **핸드오프**: 처분한 뒤에도 진행 중인 작업이 남았다. scratchpad에 핸드오프 문서를 쓰고, 다음 세션에 붙여넣을 한 줄을 출력한다.

핸드오프 문서를 바로 쓰지 않고 처분부터 하는 이유: 결정, 할 일, 아이디어는 핸드오프 문서보다 오래 살아야 한다. 핸드오프 문서는 다음 세션이 한 번 읽으면 끝나는 임시 파일이라, 거기에만 적으면 그 다음 세션에서 사라진다. 먼저 제자리로 옮기면 핸드오프 문서에는 진행 중인 추론과 막힌 지점만 남아 짧아진다.

## Context

- git 상태: !`git status --short --branch 2>/dev/null || echo "(git 저장소 아님)"`
- push하지 않은 commit: !`git log @{u}..HEAD --oneline 2>/dev/null || echo "(upstream 없음 — 브랜치를 push한 적 없으면 전부 로컬에만 있다)"`
- worktree: !`git worktree list 2>/dev/null`
- 현재 브랜치 PR: !`gh pr view --json number,title,state,url,statusCheckRollup --jq '"#\(.number) \(.state) \(.title) \(.url) checks=\([.statusCheckRollup[]?.conclusion] | unique | join(","))"' 2>/dev/null || echo "(현재 브랜치 PR 없음)"`
- 세션 기록 파일: !`find ~/.claude/projects -maxdepth 2 -name "${CLAUDE_CODE_SESSION_ID:-none}.jsonl" 2>/dev/null | head -1`
- compact 횟수: !`f=$(find ~/.claude/projects -maxdepth 2 -name "${CLAUDE_CODE_SESSION_ID:-none}.jsonl" 2>/dev/null | head -1); if [ -n "$f" ]; then grep -c '"compact_boundary"' "$f"; else echo "(기록 파일 없음)"; fi`
- 인자: `$ARGUMENTS` — `꼼꼼히`가 있으면 2단계의 기록 파일 훑기를 판단 없이 실행한다.

## 1. 모은다

아래 목록을 전부 확인한다. 목록을 고정하는 이유는, 사용자가 "남은 거 있어?"라고 물을 때마다 확인하는 범위가 달라지는 것을 막기 위해서다. 해당 없는 항목도 4단계 판정에 "확인함, 없음"으로 남긴다.

**명령으로 확인하는 것** (위 Context 출력과 세션 도구)

| 항목 | 남으면 잃는 것 |
|---|---|
| commit하지 않은 변경 | worktree를 지우거나 브랜치를 바꾸면 사라진다 |
| push하지 않은 commit | 이 기기에만 있다 |
| 현재 브랜치의 열린 PR, 실패한 check | 머지 대기인지 수정 대기인지 다음 세션이 모른다 |
| 이 세션이 만든 worktree | 세션 종료 프롬프트에서 remove를 고르면 브랜치까지 삭제된다 |
| 돌고 있는 백그라운드 작업, Monitor, cron, 실행 중인 서브에이전트 | 결과 알림을 받을 세션이 사라진다 |
| task 목록의 미완료 항목 | 세션과 함께 사라진다 |

**대화를 읽어 판단하는 것**

| 항목 | 찾는 방법 |
|---|---|
| 기록하지 않은 결정 | 사용자와 합의했지만 코드, 문서, commit 메시지 어디에도 반영하지 않은 것 |
| 미룬 논의 | "나중에", "일단 보류", "그건 따로" 로 넘긴 것, 사용자가 물었는데 답하지 않은 질문 |
| 검증하지 않은 완료 주장 | 체크 명령을 실행하지 않고 "완료", "동작한다"고 보고한 것 |
| 다시 알아내기 비싼 사실 | 환경 특이사항, 우회법, 실측한 수치의 재현 명령 |
| 작업 방식에 대한 사용자 교정 | 사용자가 "이렇게 하지 마", "앞으로는" 으로 바로잡은 것 |
| 아이디어, 글감 | 이번 범위 밖이라 접어 둔 생각 |

## 2. compact 이전 구간을 채운다

compact 횟수가 0이면 이 단계를 건너뛴다. 현재 컨텍스트에 세션 전체가 있다.

compact된 세션에서는 compact 요약의 `Pending Tasks`, `Current Work` 섹션을 먼저 1단계 목록과 대조한다. 비용이 들지 않는다.

그 다음 기록 파일을 훑을지 판단한다. 요약은 결론만 남기고 미룬 논의와 사용자 교정을 자주 빠뜨린다. 아래 중 하나면 훑는다.

- 인자에 `꼼꼼히`가 있다
- 요약에 "논의했다", "검토했다"만 있고 결론이 없는 항목이 있다
- 사용자가 compact 이전에 한 이야기를 가리키는데 요약에서 찾을 수 없다

훑지 않기로 했으면 4단계 판정에 "compact 이전 구간은 요약으로만 확인"이라고 적는다. 사용자가 판정의 한계를 알고 끝낼지 정하게 하기 위해서다.

**훑는 방법**

1. 대화 텍스트만 뽑는다. 도구 출력이 기록 파일 크기의 대부분이라, 뽑으면 1% 미만으로 줄어든다.

   ```bash
   <이 스킬 디렉토리>/scripts/extract-transcript.sh <세션 기록 파일> <scratchpad>/leave-a-will/segments
   ```

   출력은 compact 구간별 `segment-NN.txt`와 크기다. 마지막 segment는 현재 컨텍스트에 이미 있으니 제외한다.
2. 남은 segment를 순서대로 묶어 한 묶음이 150KB를 넘지 않게 나누고, 묶음마다 `model: haiku` Agent를 병렬로 띄운다. 지시문:

   ```text
   <segment 파일 경로들>을 Read로 읽어라. 사용자와 에이전트의 대화 기록이다.
   아래에 해당하는 발화를 찾아라:
   - 합의했지만 이후 코드, 문서, commit에 반영했다는 말이 없는 결정
   - "나중에", "보류", "따로" 로 미룬 논의, 답을 받지 못한 사용자 질문
   - 사용자가 에이전트의 작업 방식을 바로잡은 교정
   - 범위 밖이라 접어 둔 아이디어
   항목마다 [L줄번호] 좌표, 30자 이내 인용, 한 줄 요약을 붙여라. 같은 segment 안에서 나중에 해결된 것은 빼라. 해당 없으면 "없음".
   ```

3. 돌아온 후보는 현재 컨텍스트와 대조한다. 뒤 구간에서 이미 처리된 것은 버린다. 판단이 애매하면 좌표의 원본 줄을 열어 확인한다.

## 3. 항목별로 처분을 정한다

모은 항목을 번호를 붙여 표로 보고한다. 집계만 보이고 결정을 요청하지 않는다. 사용자가 항목 내용을 보고 처분을 정해야 하기 때문이다.

```text
| # | 항목 | 근거 | 추천 처분 |
|---|------|------|-----------|
| 1 | commit하지 않은 변경 3개 파일 | git status | 지금 처리 (commit) |
| 2 | 에러 재시도 횟수를 3으로 합의 | 대화 L1204 "재시도는 3번이면" | 문서 (ADR) |
| 3 | 파서 리팩토링 보류 | compact 요약 Pending Tasks | 이슈 |
```

표 아래에 구분선을 두고 결정 요청을 따로 적는다. 사용자는 번호로 답한다(예: "1, 3은 추천대로, 2는 버림").

**처분할 곳**

| 처분 | 실행 |
|---|---|
| 지금 처리 | commit과 push는 `commit` 스킬, 검증은 체크 명령 실행 |
| 이슈 | `git-issue` 스킬 |
| 아이디어 | `idea-note` 스킬 |
| 메모리 | 메모리 규칙에 따라 파일을 쓴다 |
| 문서 | 결정은 ADR(`decision-records` 스킬이 있으면 그것), 환경 사실은 CLAUDE.md |
| 글감 | `blog` 스킬이 있으면 capture |
| 핸드오프 | 4단계 문서의 해당 섹션에 넣는다 |
| 버림 | 아무것도 하지 않는다 |

추천 처분은 항목의 수명으로 정한다. 다음 세션 하나만 알면 되는 진행 중 추론은 핸드오프, 여러 세션에 걸쳐 참이어야 하는 결정과 할 일은 문서, 이슈, 메모리다.

worktree 삭제, 변경 버리기, 백그라운드 작업 중단은 되돌릴 수 없다. 사용자가 그 항목 번호를 지정해 "버림"이나 "중단"을 말했을 때만 실행한다.

처분을 실행한 뒤 각 항목의 결과(이슈 URL, 메모리 파일 경로, commit 해시)를 모은다.

## 4. 판정한다

**진행 중인 작업이 남지 않았으면** 잃을 것 없음을 판정한다.

```text
잃을 것 없음.
확인한 것:
- commit하지 않은 변경: 없음
- push하지 않은 commit: 없음
- 열린 PR: #42 머지 대기, check 통과
- 백그라운드 작업: 없음
- 대화: 결정 2건 ADR 반영, 미룬 논의 1건 이슈 #57
- compact 이전 구간: 기록 파일 훑음 (또는: 요약으로만 확인)
```

**진행 중인 작업이 남았으면** 핸드오프 문서를 쓴다.

- 경로: 시스템 프롬프트가 알려준 scratchpad 디렉토리의 `handoff.md`. 같은 세션에서 다시 부르면 덮어쓴다.
- scratchpad는 재부팅하면 비워질 수 있다. 다음 세션을 바로 열지 않을 것 같으면 사용자에게 알린다.

```markdown
# 핸드오프: <작업 이름>

- 작업 디렉토리: <절대 경로>
- 브랜치: <브랜치명>

## 목표
<이 작업이 무엇을 끝내려는지 한두 문장>

## 현재 상태
- 끝난 것: <commit 해시나 파일 경로로>
- 진행 중인 것: <파일 경로와 무엇을 바꾸는 중인지>
- 마지막으로 통과한 체크: <명령>

## 진행 중 추론
- 가설: <무엇을 의심하는지, 근거 좌표>
- 배제한 것: <무엇을, 왜>

## 막힌 지점
<무엇 때문에 멈췄는지. 없으면 이 섹션을 쓰지 않는다>

## 다음 한 단계
<바로 실행할 명령이나 편집. 먼저 열 파일 경로>

## 옮겨 둔 곳
- <이슈 URL, 메모리 파일 경로, 문서 경로 — 3단계 결과>
```

핸드오프 문서에 쓰지 않는 것: 이미 3단계에서 옮긴 결정과 할 일의 내용(경로만 `옮겨 둔 곳`에 적는다), 시점 실측 수치(재실행 명령으로 쓴다), 이번 세션의 진행 경위.

문서를 쓴 뒤 응답 마지막에 아래를 출력한다.

```text
핸드오프: <handoff.md 절대 경로>
다음 세션에 붙여넣기:
  <handoff.md 절대 경로> 읽고 이어가
```
