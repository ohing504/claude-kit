# git-issue 규격의 근거

SKILL.md의 판정을 바꾸려 할 때 읽는다. 실측은 자체 저장소 6곳(2026-08-05~09, 커밋 1,622건, 이슈 224건, PR 500건)과 외부 연구다.

## 이슈만 거짓을 막는 장치가 없다

| | 무엇이 거짓을 막나 |
|---|---|
| 커밋 | diff. 메시지가 diff와 어긋나면 `git show` 한 번에 드러난다 |
| PR | diff와 CI. "테스트 통과"는 CI가 빨간불이면 바로 거짓이 된다 |
| 이슈 본문 | 없음 |
| 이슈 코멘트 | 없음. 읽는 사람도 없다 |

세션은 완료가 아니라 품질 실패로 끊기는데, 그 세션도 이슈를 만든다. 그래서 이슈에는 틀리게 적혀도 다음 세션을 오염시키지 않는 것만 남기고, 검증이 필요한 내용은 PR로 보낸다. Conventional Commits 준수율은 94~100%(200커밋 표본)로 유지됐고, 이슈만 유지되지 않았다.

- **완료 조건이 병목이다.** 수용 기준이 없으면 에이전트는 "돌아가는 것"에서 멈추고 사람이 리뷰에서 그 몫을 떠안는다.
- **블록 수를 템플릿으로 제한한다.** 지시가 많을수록 준수율이 떨어진다(addyosmani가 "instruction curse"라 부른 현상). 8절 템플릿을 강제한 저장소는 `## 완료 조건` 보유율 97%였는데 그 이슈들로 backlog가 관리되지 않았다. 템플릿은 채울 칸을 만들어 분량만 늘렸다.

## 진행 상황을 어디에도 적지 않는다

- **이슈 본문**: 한 저장소에서 `gh issue edit` 498회에 close 14회, 활동 16일 중 backlog가 줄어든 날 0일, 만든 이슈의 29%(50건)를 삭제했다. 열린 이슈 전체를 읽는 데 59k 토큰이 들었다.
- **이슈 코멘트**: 코멘트 0개인 이슈가 53~86%였고 상태 갱신은 코멘트 59회 대 본문 edit 498회였다. "상태를 본문에서 빼고 코멘트에서 파생시켜라"(Astro식 트리아지)는 1인 개발에서 기각한다. 코멘트도 읽는 사람이 없고 검증 수단이 없다는 점이 본문과 같다. 코멘트는 사람이 한 줄 남기는 용도와, 착수 전 재현에 실패한 사실을 남기는 용도로만 쓴다.
- **PR**: 생성에서 닫힘까지 중앙값 12분~1시간, draft PR은 453건 중 3건(0.7%)이다. PR은 산출물이고 큐가 아니다.
- **진행 문서**: 진행 문서를 건드린 커밋이 27~34%(문서로 관리하는 저장소), 이슈로 옮긴 뒤 13%, 문서를 안 쓰는 저장소 0%였다.

## 라벨

### 체계를 다듬기 전에 조회 여부를 본다

부착률은 사람이 붙일 때만 지표가 된다. 에이전트가 스킬을 거쳐 생성 시점에 붙이면 부착률은 항상 100%다. 그때 볼 것은 라벨로 조회한 적이 있는가다.

- 측정: 세션 로그의 `tool_use`에서 `gh issue list --label` 실행 수를 센다.
- 한 저장소의 세션 14개 전수에서 `--label` 조회가 0건이었다. 이슈 32건에 라벨이 모두 붙어 있었다(2026-08-09).
- 조회에 쓰이지 않는 동안에는 축이 1개든 2개든 결과가 같다.

### 유형 라벨을 커밋 type과 맞추지 않는다

분할 기준이 다르다. 커밋 type은 changelog와 semver를 위해 나누고(`feat` minor, `fix` patch), 이슈 유형은 사용자에게 보이는 변화인가로 나눈다. gastown 라벨 가이드의 `kind/chore`는 사용자에게 보이는 동작을 바꾸지 않는 refactoring, tests, CI, tooling, build system을 하나로 묶는다.

맞추는 것이 관행이라는 근거도 없다.

- Conventional Commits 스펙은 이슈 라벨을 언급하지 않는다.
- 자동 매핑 도구(`PRConventionalCommits` 류)는 PR 제목의 type을 읽는 PR 전용이다. 이슈는 변경 전이라 type이 정해지지 않는다.
- 공개 저장소 6곳의 `gh label list`(2026-08-09) 중 커밋 type과 겹치는 것은 deno 1곳이다. angular(`type: bug/fix`, `feature`, `refactoring`), kubernetes(`kind/cleanup`, `kind/flake`, `kind/support`), rust(`C-bug`, `C-enhancement`, `C-cleanup`), vue(bug, feature request)는 커밋에 없는 어휘를 쓴다.

커밋 로그에 `refactor:`가 많다는 것은 유형 값을 늘릴 근거가 아니다.

## GitHub 기능 (2026-06 기준)

- **Issue Types**는 organization 저장소 전용이다. 확인: `gh api repos/<owner>/<repo> --jq .owner.type`.
- **Sub-issues**는 개인 저장소에서도 된다(gh v2.94.0 이상). `gh issue create --parent 100`, `gh issue edit 42 --set-parent 100`. 1단계까지만 쓴다.
