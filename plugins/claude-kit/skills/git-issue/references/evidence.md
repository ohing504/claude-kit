# git-issue 규격의 근거

본문 블록이나 라벨 규칙을 바꾸기 전에 읽는다.

## 본문 블록과 PR 머지율

출처: arXiv:2512.21426. Copilot coding agent가 이슈를 받아 만든 PR 3,180건에서, 이슈 속성 점수가 높은 이슈와 낮은 이슈의 PR 머지율 차이다. 수치는 논문 표기 그대로다.

| 이슈 속성 | 머지율 차이 | 이 스킬의 규칙 |
|---|---|---|
| self-contained | +16.65% | 제목과 `## 왜`만 읽고 착수할 수 있게 쓴다 |
| 범위 한정 | +16.44% | 작업이 둘 이상이면 이슈를 나눈다, `## 하지 말 것` |
| 기대 동작과 엣지 케이스 | +10.69% | `## 완료 조건` |
| 환경 설정 서술 | -9.4% | 환경과 아키텍처 배경은 CLAUDE.md로 보낸다 |

같은 논문에서 이슈 본문이 길수록 머지 확률이 약 9% 낮았다. 본문 글자 수 상한의 외부 근거다.

## 라벨 조회 실측

한 저장소의 세션 기록 14개에서 `gh issue list --label` 실행이 0건이었다. 그 저장소의 이슈 32건에는 라벨이 모두 붙어 있었다(2026-08-09 자체 측정). 스킬이 이슈를 만들 때 라벨을 붙이므로 부착률은 항상 100%이고, 라벨이 쓰이는지 판단하는 데 쓸 수 없다.

## 기각한 대안

- **진행 상황을 이슈 코멘트에 적는다**: 자체 저장소에서 코멘트가 0개인 이슈가 53~86%였다(2026-08 자체 측정). 코멘트도 본문처럼 아무도 다시 읽지 않고 내용이 맞는지 확인할 수단이 없다.
