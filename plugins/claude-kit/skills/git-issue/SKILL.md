# Git Issue

## Context

- 열린 이슈: !`gh issue list --state open --limit 30 --json number,title,labels --jq '.[] | "#\(.number) \(.title) [\(.labels | map(.name) | join(","))]"' 2>/dev/null || echo "(조회 실패 — 이슈 미사용 저장소일 수 있음)"`
- 현재 브랜치: !`git branch --show-current`
- 인자: `$ARGUMENTS` — `#N` 또는 숫자가 있으면 그 이슈를 여는 것이고, 나머지 텍스트는 만들거나 고칠 내용으로 읽는다. 인자가 없으면 대화 맥락에서 받는다.

## 이슈로 만들 것인가

**다음 세션의 나 또는 에이전트에게 넘길 것만 이슈로 만든다.**

| 상황 | 이슈? | 대신 |
|---|---|---|
| 이번 세션에서 끝낼 것 | ✗ | 커밋 메시지가 기록한다 |
| 다음 세션에 넘길 것 | ✓ | 이슈 본문이 그 세션의 입력이 된다 |
| 결정, 규약, 기각 이유 | ✗ | ADR — 닫힌 뒤에도 참이어야 하는 것 |
| 거친 생각 | ✗ | `idea-note` — 이슈로 만들면 곧 본문이 틀린다 |
| 진행 상황 | ✗ | **어디에도 적지 않는다** |

**만들기 전에 중복을 검색한다**: `gh search issues --repo <owner/repo> "<핵심어>" --state open`. 유사한 것이 있으면 새로 만들지 말고 그 이슈에 붙인다.

**close는 하지 않는다.** 이슈는 PR 본문 `Closes #N`으로 머지와 함께 닫는다. `gh issue close`를 직접 실행하지 않는다.

## 제목 — 증상 서술문

**판정 기준: 완료 시점에 그 문장이 거짓이 되면 닫는다.**

| ❌ | ✅ |
|---|---|
| `feat(mcp): 대화형 입력을 주 경로로` | `MCP 도구로 장부 입력과 수정이 안 된다` |
| `produce가 시나리오 단계를 갖는다` | `produce가 시나리오 없이 바로 렌더해 컷이 어긋난다` |

- **커밋 접두사(`feat:`, `fix:`) 금지.** 이슈는 변경 전이라 시제가 안 맞고, 여러 종류를 한 접두사로 못 담는다. 분류는 라벨이 맡는다
- **"만들 것의 이름"으로 쓰지 않는다.** 참과 거짓이 없으면 저장소가 어떤 상태가 돼도 닫을 근거가 안 생기고, 남는 건 본문을 계속 고치는 것뿐이다
- **비유와 은유 금지. 제목과 본문 둘 다.** 무엇이 안 되는지를 파일, 명령, 화면, 값으로 쓴다 — 제목만 읽고 무엇이 안 되는지 알 수 없으면 다음 세션은 착수 대신 본문과 코드를 다시 읽는다
  - ❌ `캐시가 계속 부푼다` / ✅ `만료된 캐시 항목을 삭제하지 않아 프로세스 메모리가 계속 늘어난다`
  - ❌ `로그인 흐름이 샌다` / ✅ `로그인 성공 후 세션 쿠키를 저장하지 않아 새로고침하면 로그아웃된다`

## 본문

`gh issue create --body-file <path>`로 전달한다. 인라인 heredoc은 깨진 셸 명령을 자주 만든다. 표준입력(`--body-file -`)과 `gh api`는 검사할 수 없어 hook이 막는다.

```markdown
## 왜
(현상, 원인, 막히는 것을 쓴다)

## 착수 전 합의할 것        ← 정할 것이 없으면 이 블록을 쓰지 않는다
- 선택지를 나열하고 각각의 근거 좌표를 붙인다
  (`compile-facts` / `gather-facts` — docs/decisions/naming.md:8이 대칭을 정한다)

## 완료 조건
- [ ] 판정할 명령이나 관찰 가능한 동작. 테스트가 필요하면 계층 명시

## 시작 지점
- src/lib/routes.ts:10-16      ← 지금 열어 확인 가능한 좌표 (선택)
- 재현: `pnpm test -- routes`   ← 수치가 아니라 명령

## 하지 말 것
(범위 밖)
```

**본문은 1,600자, `## 착수 전 합의할 것`이 있으면 1,900자 이하.** `issue-guard` hook이 `gh issue create`와 `gh issue edit`를 가로채 초과분과 `## 왜` 누락을 deny한다. edit의 `## 왜` 누락은 경고까지만 한다 — 옛 규격으로 열린 이슈를 고치는 경로다.

**블록을 더 늘리지 않는다.** 블록이 늘면 채우려고 쓴 문장이 늘고, 읽는 세션이 그것을 걸러야 한다. 8절 템플릿을 쓴 저장소는 완료 조건 보유율이 97%였는데 그 이슈들이 닫히지 않고 쌓였다.

### 본문 밖으로 보낼 것

아래는 틀리게 적혀도 읽는 쪽이 걸러낼 수 없다. 상한을 넘겼다면 대개 이것들이 들어 있다.

| 금지 | 보낼 곳 |
|---|---|
| 시점 의존 실측 — `748줄`, `16.8k 토큰`, 커밋 permalink | 재실행 명령 `wc -l <path>` |
| 확정된 결정과 그 근거 | ADR. 이슈는 그 경로만 가리킨다. **아직 안 정한 것은 빼지 말고 `## 착수 전 합의할 것`에 남긴다** |
| 환경과 아키텍처 배경 | CLAUDE.md 또는 AGENTS.md |
| 진행 상황 | 적지 않는다. 상태는 라벨에서 읽는다 |

시점 실측을 적으면 코드가 바뀌는 순간 본문이 통째로 거짓이 되고, 다음 세션은 착수 대신 재검증을 한다. 실제로 같은 파일을 가리키는 이슈들이 서로 다른 줄 수를 적은 채 동시에 열려 있었고 전부 틀렸다.

### `## 왜` — 제목을 되풀이하지 않는다

무엇이 안 되는지는 제목이 이미 갖는다. 이 블록은 아래를 더한다.

| 쓸 것 | 없으면 |
|---|---|
| 현상 | 제목과 같은 말이 된다 |
| 원인 | 착수 세션이 증상만 덮는다 |
| **막히는 것** | **손해를 재지 못해 완료 조건만 형식으로 통과시킨다** |

### `## 착수 전 합의할 것` — 안 정한 것을 완료 조건에 확정으로 적지 않는다

이슈를 쓰는 세션이 정한 것과 사용자가 합의한 것은 다르다. 합의 안 된 값을 완료 조건 체크박스에 적으면 착수 세션은 그것을 확정 지시로 읽는다.

- **체크박스를 쓰지 않는다.** 완료 조건과 섞이면 채우면 끝나는 것으로 읽힌다
- **`정한다`로 끝내지 않는다.** 후보를 나열하고 각각의 근거 좌표를 붙인다

Rust RFC `Unresolved questions`, PEP `Open Issues`, KEP `<<[UNRESOLVED]>>`, spec-kit `[NEEDS CLARIFICATION]`이 모두 미결을 본문에 적는다. 이슈 밖에 적으면 다음 세션이 그 파일을 열 이유가 없다.

### `## 완료 조건` — 판정이 실제로 되는지 본다

- **확정 값(이름, 경로, 수치)을 적을 때는 그 값을 정한 기준을 함께 쓴다.** 기준이 없으면 위 블록으로 올린다
- **판정 명령은 쓰기 전에 실행해 지금 몇 건이 걸리는지 본다.** 실측 사례 — `git grep 'subject'`가 97개 파일에 걸려 그 조건은 충족되지 않는다. 단어 경계는 `-w`나 `-P`로 준다(`git grep -E`는 `\b`를 받지 않아 0건이 나온다). 경로와 제외 pathspec으로 좁히고(`-- plugins app/src ':!app/src/features/stats'`), 그래도 남는 오탐은 `## 하지 말 것`에 적는다
- **동작 보존 변경이면 착수 전에도 통과하는지 먼저 확인한다.** 지금 실패하면 그 조건이 착수를 막는다

## 라벨

```text
상태(하나만 붙인다):  now / next / later
유형:                feat / fix / chore / docs
```

에이전트 파이프라인이 있을 때만 `needs-repro`, `agent-working`을 더한다. 축을 늘리면 부착이 멈춘다 — 축을 둘로 늘린 저장소에서 부착률이 9일 만에 100%에서 0%로 떨어졌고 아무도 알아채지 못했다.

저장소에 이미 다른 라벨 체계가 있으면 그것을 따르되, 새로 축을 만들지 않는다.

## 이미 있는 이슈를 열었을 때

### 착수할 때

**`## 착수 전 합의할 것`이 남아 있으면 구현하지 않는다.** 그 블록의 항목을 사용자에게 제시해 합의하고, 합의한 것을 본문에 반영한 뒤 착수한다.

그 블록이 없어도 완료 조건에 합의 없이 적힌 확정 값(이름, 경로, 수치)이 보이면 같게 다룬다 — 그 값을 정한 기준이 본문에 없으면 합의 대상이다.

### 본문을 고칠 때

**본문 재작성은 마지막 수단이다.** 한 저장소에서 `gh issue edit` 498회에 close는 14회였다 — 고쳐 쓰기만 반복했다.

- 착수하려는데 본문이 코드와 어긋나면, 고쳐서 착수하지 말고 **먼저 코드에서 재현**한다
- 재현되지 않으면 사실을 코멘트로 남기고 멈춘다. 본문을 추측으로 갱신하지 않는다
- 전제가 사라진 이슈(가리키는 파일이 없거나 완료 조건이 이미 충족)는 close 후보로 보고한다
- **옛 규격 이슈(`## 무엇을`)를 여는 김에 `## 왜`로 바꾸지 않는다.** 착수하거나 본문이 틀린 것을 확인했을 때만 고친다

## Execution

1. 인자에 `#N`이 있으면 `gh issue view <N>`으로 읽고 위 "이미 있는 이슈를 열었을 때"로 간다
2. 없으면 이슈로 만들 것인지 판정. 아니면 대신 갈 곳을 한 줄로 알리고 종료
3. 중복 검색
4. 제목과 본문 초안을 응답 본문에 코드블록으로 제시하고 확인
5. `--body-file`로 생성. 생성된 URL 출력
